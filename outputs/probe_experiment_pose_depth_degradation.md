# 探针实验方案：位姿/深度退化到底让现有方法掉多少点

> [!abstract] 目的
> 在投入方法设计之前，用**最低成本**判定一件事：SceneFun3D 上现有方法对位姿/深度误差到底敏不敏感。
> 这是「去位姿依赖」改进能否成立的**生死判据**。掉得多，故事成立；掉得少，及时止损。
>
> [!warning] 方案性质
> 本方案中的**数据格式事实**（`.traj` 字段、资产构成）来自已核验的 SceneFun3D 官方文档；
> **实验设计、档位设置、判读阈值**均为 `[分析者设计]`，非任何论文原文主张，阈值可在执行前调整。

---

## 0. 先定死决策规则（防止事后合理化）

**在执行任何实验之前**写下判读标准，避免看到结果后再编故事。

| 在「真实误差量级」处的 AP50 跌幅 | 判定 | 行动 |
|---|---|---|
| **> 5 个点** | 🟢 强信号 | 立项。「去位姿依赖」可作论文的支撑证据之一 |
| **2 – 5 个点** | 🟡 弱信号 | 只能做副产物，**不能当主 claim**，需换更强的叙事 |
| **< 2 个点** | 🔴 null result | **放弃这条线**，止损 |

**附加判据（可能救回弱信号）**：若总体跌幅小，但**最小尺度部件子集**（GT 点数最小 25%）跌幅 ≥ 2 倍于总体，则故事仍成立且更聚焦——affordance grounding 的价值恰在小部件，这个分层结论本身也可发表。

## 1. 为什么先用 oracle 探针，而不是端到端

**核心观察 `[分析者推演]`：位姿只进入 lifting 阶段。**

Fun3DU 的管线是 `LLM 解析 → OWLv2 + RobustSAM 找 context object → Molmo 找 functional part → 投影聚合到 3D`。前几步只吃图像，**与位姿无关**（需回代码确认，见 §6 待办）。

由此可得两个极大的效率优化：

1. **可完全跳过 VLM，用 GT 反投影造 oracle 2D 掩码。** SceneFun3D 的标注是 3D 点索引，用 `hires_poses` + `intrinsics` 投影到各视角即得该视角的完美 2D 掩码。再把这些掩码用**扰动后的位姿**聚合回 3D。
   - 同位姿投影出去再投回来 = 完美重建（得上界，验证实现正确）
   - 扰动位姿投回来 = 纯位姿误差造成的退化
   - **变量被彻底隔离**，且是纯几何计算，**秒级完成**
2. 若要端到端验证，**2D 掩码可缓存复用**：跑一次昂贵的 VLM 推理后，每档只重跑便宜的投影聚合，成本降一个数量级。

## 2. 实验矩阵

### Phase 1 — Oracle 探针（目标：1–2 小时内出曲线）

| 变量 | 档位 | 说明 |
|---|---|---|
| 基线 L0 | 无扰动 | 得上界，同时验证投影/反投影实现正确（IoU 应接近 1.0） |
| 位姿 L1–L4 | 见 §3 参数 | 分离旋转与平移 |
| 深度 D1–D4 | 见 §3 参数 | 分离加性与乘性 |
| 位姿+深度联合 | 各取中档 | 模拟真实部署（两者都估计） |

- 场景数：**先用 3 个场景跑通，再用 10 个场景出结论**
- 每场景任务数：**全用**（每场景约 15 条，oracle 实验无推理成本）
- 随机种子：**每档 3 个**，报告均值 ± 标准差

### Phase 2 — 端到端验证（仅当 Phase 1 有信号才做）

用 Fun3DU 真实管线，缓存 2D 掩码后在各档位重跑投影聚合。

- 场景数：10 个；每场景 5 条任务
- 成本估算（据 T-FunS3D 表 III：`Fun3DU 实例分割 1920s/场景`、`功能分割 167s/查询`，A40）：
  - 一次性跑通：1920s × 10 ÷ 3600 ≈ **5.3 h**；167s × 50 ÷ 3600 ≈ **2.3 h** → 合计约 **7.6 h**
  - 之后每档仅重跑投影聚合：**分钟级**
- ⚠️ 若改用 TASA / UniFunc3D 则成本更高（需 72B / 30B 模型），**不建议**用于探针

## 3. 扰动参数化

### 3.1 位姿扰动（对每个视角的 $[R|t]$ 独立采样）

- **旋转**：左乘 $R_{pert}=\exp(\theta[\omega]_\times)$，$\omega$ 为随机单位轴，$\theta\sim\mathcal{N}(0,\sigma_{rot})$
- **平移**：$t_{pert}=t+\delta$，$\delta\sim\mathcal{N}(0,\sigma_{trans}^2 I)$

| 档位 | $\sigma_{rot}$ | $\sigma_{trans}$ | 定位 |
|---|---|---|---|
| L0 | 0 | 0 | 基线上界 |
| L1 | 0.5° | 1 cm | 轻微 |
| **L2** | **1°** | **2 cm** | **≈ 官方提到的 ARKit 插值错位量级（1–2 cm）** |
| L3 | 2° | 5 cm | 明显退化 |
| L4 | 5° | 10 cm | 严重（真实 SLAM 漂移量级） |

> 参考量级：1–3 m 距离下，2 cm 平移约等效 0.4°–1.1° 的视角偏差；故 L2 的旋转与平移量级大致自洽。

### 3.2 深度扰动

| 档位 | 形式 | 参数 | 定位 |
|---|---|---|---|
| D0 | 无 | — | 基线（GT 深度） |
| D1 | 加性 | $\sigma_d = 1$ cm | 近场 LiDAR 量级 |
| D2 | 乘性 | $\sigma_{rel}=2\%$ | **远场误差随距离增长，更真实** |
| D3 | 混合 | 1 cm + 2% | 常见 LiDAR 误差模型 |
| D4 | 乘性 | $\sigma_{rel}=5\%$ | 单目估计深度量级 |

> 优先看 **D2/D3**：AffordMem 的 $\tau_{min}=0.05$ m 深度一致性阈值是在 **GT 深度**下调出来的，一旦用估计深度该阈值即失效。

## 4. 关键：把人造曲线锚定到真实误差

加噪曲线的通病是"人造"。用官方数据自身消除这个质疑：

**SceneFun3D 同时提供两套位姿：**
- `lowres_poses.traj` —— ARKit 位姿，**ARKit 系**
- `hires_poses.traj` —— SuperGlue + COLMAP 位姿，**Faro 系**（官方称更准，用于避开 ARKit 的 1–2 cm 插值错位）

**做法**：把两套位姿统一到同一坐标系后，统计同一时刻的位姿差（旋转角差、平移距离差），得到**真实位姿不确定性的分布**（中位数、p90）。把这个数字**标到 §3 的加噪曲线横轴上**。

> ⚠️ 工程代价：lowres 位姿 60 fps 配 256×192，hires_wide 10 fps 1920×1440 → 需按 `.traj` 的 `ts` 字段做时间戳对齐；坐标系转换需对 `_transform.npy`（4×4，Faro→ARKit）**求逆**。可行但琐碎，**放在 Phase 1 出结果之后再做**。

**判读**：若真实误差落在曲线的**平坦段** → 故事死；落在**陡降段** → 故事活。

## 5. 分层报告（必须做）

按 GT 掩码点数分位，分别报 AP：

| 子集 | 含义 |
|---|---|
| 最小 25% | 把手、旋钮、开关等**小部件**（affordance 的真正目标） |
| 中 50% | 抽屉面板、门板 |
| 最大 25% | 大表面 |

**预期 `[分析者推演]`**：位姿误差对小部件的影响应显著大于大表面（同样 2 cm 误差，对 5 cm 的把手是 40% 偏移，对 50 cm 的门板是 4%）。即使总体跌幅不显著，**小部件子集跌幅显著**就足以支撑故事。

## 7. 风险与备选

| 风险                                                                      | 应对                                                                  |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 测出 null result（跌幅 < 2 点）                                                | 放弃位姿线，回到「置信度校准」主叙事，改从别的角度论证                                         |
| 审稿人称"这是 3D 重建的老问题"（BARF / CF-3DGS / InstantSplat / DUSt3R 已做 pose-free） | 需论证 affordance 特殊性：**小部件 + 稀疏语义监督 + 语义驱动 ≠ 稠密重建**。目标不是重建几何，而是定位几十个点 |
| 「不依赖相机参数」已被 HAMMER（物体级）claim                                            | 主 claim 必须落在**置信度**上，去位姿只作证据                                        |
| `lowres_poses` 时间戳/坐标系转换过于繁琐                                            | 跳过 §4，改用「换用单目估计深度」做真实退化锚点——同样真实且无需折腾坐标系                             |

## 8. 这条线最终要落成什么样（若探针通过）

叙述模板（**不是**"我们提出位姿鲁棒的方法"）：

> 现有方法把 2D 语义经位姿投影**硬绑定**到 3D，投票时各视角是否互相支持这一信息被压缩成 0/1 后丢弃。我们改用一致性加权的**软对应**——它在特征空间而非欧氏空间建立跨视角关联，天然输出逐点置信度；**不需要精确位姿只是它的副产物**。

- 主 claim = **输出的置信度可校准**
- 去位姿 = 最强的一条证据
- 必须证明：**位姿准确时也不输**（否则是补丁而非新机制）
- 必须证明：**置信度模块不可分解**（去掉即退化到基线）
