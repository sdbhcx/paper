# 场景级 Affordance Grounding：方法谱系、性能对照与迁移点

> [!summary] 一句话总结
> 场景级 affordance grounding 的核心任务定义来自 **SceneFun3D**（CVPR 2024）：给定整场景点云 + 位姿 RGB-D + 自由文本任务（"打开放花的木柜最下层抽屉"），输出**可操作功能部件**（把手/旋钮/开关）的 3D 掩码，而非物体级实例。方法可分三条路线：**2D 提升到 3D（免训练，主流）**、**3D 渲染成 2D 喂 MLLM（可训练 / CoT）**、**视频或第一人称驱动**。关键共识是：开放词汇 3D 分割在这条线上几乎失效（AP≈0），而"免训练 VLM + 几何聚合"已经反超训练型方法。

> [!warning] 笔记性质说明
> 本笔记为**综述型对比笔记**，不是单篇精读。所有数字均标注来源论文；标注 `[分析者推演]` 的内容为本人的归纳与判断，非任何论文原文主张。跨论文数字**不可直接横比**（见 §4 口径警告）。

## 1. 范围界定：什么是"场景级"

| 层次 | 输入 | 输出 | 典型代表 |
|---|---|---|---|
| **物体级（object-centric）** | 单个物体点云（CAD 或重建）+ 文本 | 该物体表面的 affordance 分割 | HAMMER、LASO、IAGNet、3DAffordSplat、VAGNet、VideoAfford、3D-AffordanceLLM |
| **场景级（scene-level）** | 整场景点云 + 多视角位姿 RGB-D + 任务文本 | 场景中**某个被指代实例的功能部件**的 3D 掩码（+ 可选的运动参数） | SceneFun3D 系列：Fun3DU、TASA、AffordBot、T-FunS3D、UniFunc3D、AffordMem、ThinkAfford |
| **第一人称场景级** | 第一人称交互视频 + 3D 场景 | 与视频中交互对应的场景可交互区域 | Ego-SAG/VSAD、EgoAfford |

划分依据 `[分析者推演]`：**是否需要在场景里先做实例消歧**（"从上数第二个把手"）是场景级与物体级真正的分水岭，而不是"点云大不大"。物体级方法把实例给定了，场景级必须自己找。

本库已有的 VAGNet / VideoAfford / HAMMER / IAAO 属于物体级，本笔记不展开。

## 2. 问题形式化

给定：
- 场景点云 $PC=\{p_i\in\mathbb{R}^{3(+3)}\}_{i=1}^{M}$（可含颜色）
- $N$ 张已标定多视角图像 $V=\{v_i\}_{i=1}^{N}$（相机内外参已知）
- 自然语言任务描述 $T$

输出：逐点二值掩码 $M\in\{0,1\}^{M}$，标记完成任务所需交互的功能区域。

**SceneFun3D 定义的三个任务**（[原文]）：
1. **Functionality segmentation**：分割所有功能交互元素实例并给出 affordance 标签（无任务条件）。
2. **Task-driven affordance grounding**：给定任务描述，预测需交互的功能元素实例掩码 + 动作标签。
3. **3D motion estimation**：额外推断运动参数（运动类型：平移/旋转；轴方向）。

**AffordBot 的扩展形式**（[原文]）：输出结构化三元组 $\{(M_i, T_i, D_i)\}_{i=1}^{K}$，即掩码 + 运动类型 + 运动方向。这是把"在哪操作"和"怎么操作"统一的第一篇。

> [!note] 任务边界
> 输出只回答"应当与哪里交互"，**不回答**机械臂如何到达、以何种姿态接触、施加多大力、操作是否成功。整条线目前**全部是开环感知评测**，没有闭环机器人验证。

## 3. 基准数据集

### 3.1 SceneFun3D（事实上的唯一主基准）

| 项 | 内容 |
|---|---|
| 出处 | CVPR 2024（Delitzas, Takmaz, Tombari, Sumner, Pollefeys, Engelmann；ETH / TUM / Google） |
| 规模 | 项目页称 **710 个高分辨率真实室内扫描、14.8k+ 细粒度交互标注**；论文评测常用子集为 **230 个场景、14.8k 标注** |
| 常用划分 | Split0 = 30 scenes（val），Split1 = 200 scenes（train） |
| 每场景 | 约 1800 张（TASA 笔记记为约 100 张"高分辨率"）位姿 RGB-D；约 15 条自由文本任务描述 |
| 标注内容 | 功能元素 3D 实例掩码 + affordance 标签（9 类）+ 运动参数 + 自然语言任务描述 |
| 指标 | AP25 / AP50（IoU 阈值 0.25 / 0.50 下的 AP）、mAP（阈值 0.50–0.95 步长 0.05）、mIoU、AR |

> [!caution] 待核对
> 项目页的"710 场景"与论文正文的"230 场景"关系未明确（可能 710 为总扫描数、230 为带完整标注的子集）。引用规模时建议写"230 个标注场景（常用划分 200/30）"并注明来源。**场景点数最高约 1300 万点，而标注功能区域仅数百点**，正负样本极度不均衡（TASA 笔记）。

### 3.2 VSAD（第一人称路线）

- 出处：随 Ego-SAG 提出，arXiv 2409.19650（2024-09-29）。
- 构成：Ego4D + EPIC-100 的第一人称视频，配 ScanNetV2 + Matterport3D 的 3D 场景。
- 规模：3814 段第一人称视频 + 2086 个 3D 场景，17 类 affordance、16 类交互目标、7690 个交互区域。
- 特点：视频与场景是**多对多松配对**（一个场景可对应多段不同交互视频），不要求严格一对一。
- Ego-SAG 结果：mAP 10.65（基线 3.48），RC25 66.52。

## 4. 方法谱系

### 路线 A：2D 提升 3D（免训练 / training-free，当前主流）

共同范式 `[分析者推演]`：**不让 3D 网络理解语义，只让 2D 基础模型负责语义与世界知识，用几何投影 + 多视角一致性把结论落到 3D 上。**

| 方法 | 出处 | 管线 | 关键设计 |
|---|---|---|---|
| **Fun3DU** | CVPR 2025 | LLM CoT 解析任务 → 由"打开天花板灯"推出要操作"开关" → VLM 在精选视角定位 → SAM 分割 → 多视角掩码投影回点云投票聚合 | 首个证明"零训练 + 2D 世界知识"可解场景级功能分割；多视角多数投票代替特征对齐 |
| **T-FunS3D** | ICRA 2026（TU Delft） | 离线建**开放词汇场景图**（Mask3D 实例 + FG-CLIP 视觉嵌入节点；**边在查询时临时计算**而非预存全图）→ Qwen3-14B 抽任务本体（上下文对象/功能部件/参照对象/空间关系，JSON 输出）→ 只对相关实例用 Molmo+SAM 做部件分割 | 层级两阶段避免整场景穷举；`masked crop` 缓解前景-背景偏置；SAM 取**最小 mask** 而非最高置信 mask；每查询约 78s（A40） |
| **TASA** | AAAI 2026（北理工等） | 任务感知选视角（CLIP 整句相似度 + 功能概念相似度加权，取 top-K=10）→ VLM 预测候选点 → **双重检查**（反向验证 + 回退查询）→ SAM 出 2D 掩码 → 投影得粗 3D 掩码 → 只取 8192 点邻域用 **Point Transformer** 几何细化 | 由粗到细、语义与几何**显式分工**；FLOPs −38.6%、推理时间 130.26s→37.61s |
| **UniFunc3D** | arXiv 2603.23478 | 两轮主动**时空** grounding：Round1 采样 N=64 帧（512×384，K=4 次不同时间偏移）粗选帧；Round2 在选中帧的 $2\Delta+1$ 时间窗内精细定位 → SAM3 出掩码 → 多视角一致性热图（阈值 τ=0.7）投票成 3D 掩码 | 引入**时间维度**（不只多视角还有时序上下文）；Qwen3-VL 8B/30B + SAM3，全程冻结 |
| **AffordMem** | arXiv 2605.11616 | 两种记忆：① **跨场景 affordance 记忆库**——类别级"带 mask 覆盖的 RGB 图像"记忆，查询时检索最相似样本作为视觉 prompt，教 VLM 找"可握的把手面"而非整块抽屉面板；② **场景内空间记忆**——2D grounding 结果提升为 3D 候选池并组织成场景图，用 LLM 做序数/关系消歧（"从上数第二个"） | 把两个失败模式显式建模为两类"记忆缺失"；Qwen3-VL-32B + SAM3；深度一致性滤波（k=3, τmin=0.05m）、多视角投票（ρ0=0.70, θvis=3, DBSCAN ε=0.03m）、K=20 |

### 路线 B：把 3D 渲染成 2D 喂给 MLLM（可训练 / CoT）

| 方法 | 出处 | 管线 | 关键设计 |
|---|---|---|---|
| **AffordBot** | NeurIPS 2025（中科大 / SUTD / 港中深） | 3D 点云渲染 **360° 环绕视角图** → Mask3D（在 ScanNet200 上微调 1000 epochs）出部件提议 → 为每个部件生成**几何-语义描述符** `[xyz, whl, 语义 affordance]` → 三步 CoT：**主动选视角 → 选部件 ID → 预测运动类型与轴方向** | 输出结构化三元组 $(M_i, T_i, D_i)$；自适应标签细化（ALR）避遮挡；渐进式掩码膨胀缓解小部件漏检。**不依赖视频输入** |
| **ThinkAfford** | ICLR 2026 投稿 **已 withdrawn**；arXiv v1 = 2608.10981（2026-08-11） | **解耦**两阶段：① Affordance Proposal Generation（APG）——可学习 affordance prompt + 多级视觉特征预测交互条件热图，提取**可变数量的细粒度提议**，不需要解析出的物体/部件名做分割提示；② Visual-Prompted Affordance Reasoning（VPAR）——在带编号的提议叠加图上用完整指令做 "think-then-answer" 推理，返回 ID；③ 用 **GRPO** 训练，奖励来自提升后的 3D overlap | 提议生成（高召回）与指令推理（高精度）**解耦**，避免 VLM 直接当分割器用；GRPO 选择准确率 72.1% vs SFT 63.4% |

### 路线 C：视频 / 第一人称驱动

| 方法 | 出处 | 管线 | 关键设计 |
|---|---|---|---|
| **Ego-SAG** | arXiv 2409.19650（2024-09-29），会议出处待核对 | 视频编码器 + 场景编码器（体素化点云）→ **ISA 模块**插在 3D U-Net 每个解码层：FPS + kNN 提子区域特征，多头交叉注意力把**视频交互意图**与子区域布局关联，给搜索空间打"聚光灯" → **BQD 双向查询解码器**：可学习双向 query 在视频特征与 3D 特征间迭代对齐 → 3D 掩码 | 训练用 **multi-positive contrastive loss**（一个房间可有多个有效交互点）；VSAD 数据集 |
| **EgoAfford** | arXiv 2608.04533 | 第一/第三人称观测 + 高级任务 → 3B 模型 **EgoLens** 同时**生成剩余计划**并**分割下一步动作的三个语义角色的部件级区域**：直接物体 $M_o$ / 工具 $M_s$ / 目的地 $M_d$ | 从"单目标单步"推进到"多步任务导向 + 多角色分配"；严格说是图像/桌面级而非 3D 点云场景级，但问题脉络一致 |

> 1. **同一方法在不同表里不同**：Fun3DU 在 TASA / AffordMem / UniFunc3D 表中是 AP50 16.9 / AP25 33.3 / mIoU 15.2；在 AffordBot 表 1 中却是 mIoU 11.5 / AP 6.1 / AP50 12.6 / AP25 23.1。

> **建议做法**：在自己的工作中引用时，标注"方法 × 来源论文 × split"，并且**优先比较同一张表内的相对提升**，不要跨表比较绝对值。

## 6. 跨论文的消融洞察（哪些设计真的有用）

> 以下每条标注来源；`[分析者推演]` 为本人的跨论文归纳。

1. **开放词汇 3D 分割在此任务上近乎失效**（OpenMask3D/LERF/OpenIns3D AP≈0，但 AR 不低）→ 说明失败在**排序/粒度**而非召回：它们能产生相关区域，但无法把正确的**小部件**排到前面。 `[跨论文一致观察]`
2. **任务解析必须落到"可操作部件"而非"物体名"**：Fun3DU 的 CoT、T-FunS3D 的任务本体抽取、TASA 的功能概念加权选帧，三者独立地得出同一结论。
3. **先剪枝视角、再细算几何，两级剪枝都有效**：TASA 的消融显示"仅选帧"使 mIoU 4.4→11.3（改善空间覆盖与一致性），"仅双重检查"使 mAP 3.9→13.1（改善严格定位），两者互补而非同质过滤。
4. **几何细化提高严格指标、可能降低宽松指标**：TASA 的 AP50 +10.0 而 AP25 −4.7（相对 Fun3DU）→ 掩码变紧而非全面变好。**读表时 AP25 高可能只是"粗略覆盖了附近区域"**。
5. **3D 细化阶段加模态反而退化**：TASA 表 4 显示 3D 模块仅用几何最优，加颜色或文本均退化（最差组合 mIoU 降至 2.8）。 `[原文]` 这是"数据规模下模态质量 > 模态数量"的负面证据。
6. **分割提议质量是主要瓶颈**：AffordBot 表 4 显示把 Mask3D 提议换成 GT 提议，AP 15.5→35.7、AP50 20.0→39.4；再换 GT 视角也只到 38.3/42.3。**上游分割远远比下游 MLLM 推理更卡脖子**。
7. **GRPO 优于 SFT 做"选择器"**：ThinkAfford 中 VPAR 选择准确率 GRPO 72.1% vs SFT 63.4%，且 APG 在 IoU=25% 下达 77.5% 召回 → 支持"高召回提议 + 高精度推理"的解耦设计。
8. **两个工程细节被反复验证**：T-FunS3D 的 `masked crop`（缓解前景-背景偏置）与"取 SAM 最小 mask 而非最高置信 mask"（避免把整物当部件）；AffordBot 的 ALR（自适应标签避遮挡）。
9. **记忆/上下文机制专门用于消歧**：AffordMem 消融显示跨场景记忆主要提升细粒度定位（去掉后 AP50 20.39→19.67），场景内空间记忆（场景图）贡献更大的序数消歧增益（去掉后 20.39→13.21）。**"记住全局布局"比"记住类别外观"更关键**。
10. `[分析者推演]` **免训练方法反超训练型方法**（UniFunc3D-30B 31.24 AP50 vs TASA 26.9 / AffordBot 20.0）的真实原因，可能不是"免训练更好"，而是**训练型受限于 30 个场景的训练集规模**（SceneFun3D 只有 200 个训练场景），而免训练直接继承了 2D 基础模型的海量先验。这条线往上走的关键瓶颈是**3D 标注规模**，不是架构。

## 7. 共同局限

### 7.1 多篇论文共同的结构性问题 `[分析者推演]`

1. **单一数据集**：全部在 SceneFun3D 上评测，无跨数据集泛化测试。
2. **全开环，无闭环验证**：没有任何一篇验证"掩码质量 → 真实操作成功率"的相关性。缺接触姿态、可达性、碰撞、力反馈。
3. **严重依赖相机标定与位姿**：2D→3D 投影路线天然如此，位姿噪声的影响缺乏系统评估。
4. **强依赖闭源/大型基础模型**：Qwen3-VL-32B/72B、GPT-4o、SAM3 等，推理成本高、不可控；换 backbone 的敏感性研究普遍不足。
5. **小部件与正负样本极端不平衡**：场景 1300 万点 vs 标注数百点，是所有方法 AP 绝对值都停留在 20–30 量级的根本原因。
6. **复现信息普遍不足**：超参、随机种子、多次运行方差、计时边界（是否含 VLM 调用与网络传输）常缺失。
7. **评测协议不统一**（见 §5.3），导致领域内数字难以公平排序。

### 7.2 各篇作者自述的局限 `[原文]`

- **TASA**：单一数据集与室内域；颜色/文本模态退化说明结论受限于小数据；模块归因不完整；双重检查仍是模型自我验证；无闭环机器人验证；固定 8192 点邻域对不同尺度部件未必最优。
- **ThinkAfford**：论文已被 ICLR 2026 **withdrawn**，仅 arXiv 预印；8 页短文，实验规模有限。
- **Ego-SAG**：未来工作自述需探索动态 query 策略与更强的几何建模以细化掩码边界。

## 8. 批判性分析：与本库 HOI 点云路线的关系

> 本节全部为 `[分析者推演]`，是本笔记的"用处所在"。

### 8.1 三条可直接借鉴的机制

| 场景级机制 | 迁移到 "text + 3D HOI 点云 → 3D MLLM → intent embedding" 的落点 |
|---|---|
| **先剪枝、再细算**（TASA 的 top-K 视角 + 局部 8192 点邻域） | HOI 点云 token 化时做**接触感知采样**：先在粗粒度上定位"可能接触区"，再在该邻域内高密度 token 化。这与已定的"接触感知 token 放置"原则完全一致，且 TASA 证明了该归纳偏置在此类任务上有效 |
| **高召回提议 + 高精度推理解耦**（ThinkAfford 的 APG + VPAR） | 正好对应已定的"**先 3D 接触 grounding 再生成 intent embedding**"：把"接触区在哪"（几何提议）与"意图是什么"（MLLM 推理）拆成两个可分别优化、可分别消融的模块，而不是让 MLLM 一口吞 |
| **跨视角/跨样本一致性投票**（UniFunc3D 的热图投票、AffordMem 的深度一致性滤波） | 若 2D HOI 图经 VGGT 类前馈重建得到 HOI 点云，**多视角一致性**是现成的监督信号，可用来筛掉重建噪声导致的假接触点 |

### 8.2 一个可以直接反驳"审稿人质疑"的证据

用户方向的核心担忧是"HOI 点云压进 3D MLLM 时几何会丢失"。场景级这条线给出了**反向的强证据**：UniFunc3D / AffordMem 用**冻结的 2D VLM + 几何投影聚合**就反超了所有训练型 3D 方法——说明**几何信息的保住与否，取决于是否有显式的几何承载通道（投影/投票/局部几何网络），而不是靠端到端训练**。这直接支持已定的设计原则 ③（解码器双流条件：intent embedding + 显式 3D 接触几何都送入）与 ④（把显式 3D 接触几何作为蒸馏目标）。

### 8.3 场景级与用户方向的关键差异（不要照搬）

- 场景级方法**几乎不使用物体级 HOI 几何**（人手/交互姿态），它们用的是"任务文本 + 静态场景"。用户的设定是**反过来**：HOI 点云里已经有交互证据，任务是从中提取并泛化到新物体。
- 场景级的"空间关系消歧"（"从上数第二个"）在单物体 HOI 点云设定下**不存在**，因此 AffordMem 的场景图机制对用户方向**价值有限**；真正值得抄的是它的**类别级记忆作为视觉 prompt** 这个思路（可类比"接触先验记忆库"）。
- 场景级全部在**静态扫描**上评测，用户的 HOI 点云来自**单目前馈重建**，噪声与缺失更严重 → 多视角一致性/置信度加权的必要性更高。

### 8.4 一个尚未被解决的空白 `[分析者推演]`

场景级方法把"如何操作"（运动类型 + 轴方向）当作**分类任务**（AffordBot 的 $T_i, D_i$），而用户方向关心的是**稠密接触几何**（接触点/接触面/接触姿态分布）。目前没有一篇场景级工作输出稠密接触场——这是一个可占的位：把 SceneFun3D 的"运动参数"细化为"接触区域 + 接触方向场"，既是场景级任务的自然延伸，也正好是用户 intent embedding 应该解码出的东西。
